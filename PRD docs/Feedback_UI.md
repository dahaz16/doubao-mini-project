
# Feedback UI
## 项目背景
本模块是小程序中的“用户反馈”功能弹窗 (`feedback-modal`)。
主要目的是让用户在与 AI 互动过程中，能随时通过文本或语音的方式提交反馈意见。
反馈弹窗是一个覆盖在当前页面（如采访页 `interview`）上的模态框，包含 AI 形象展示、反馈引导文案、反馈内容输入（语音转文字）、以及提交/取消操作。
## 当前各 UI 控件的逻辑与状态
### 1. 弹窗整体
- **位置**：全屏覆盖 (`fixed`), `z-index: 1000`。
- **背景**：半透明黑色遮罩 (`rgba(0,0,0,0.5`) + 居中白色卡片。
- **卡片样式**：白色背景，圆角 40rpx，Padding 50rpx 40rpx。
### 2. AI 头像 (`.ai-avatar-wrapper`)
- **位置**：卡片顶部，距离上边缘 30px。
- **当前样式逻辑**：
  - 容器尺寸：300rpx (宽) x 150rpx (高)。
  - 图片模式：`aspectFill`。
  - 圆角：20rpx。
  - **调试状态**：WXML 中为了调试尺寸添加了临时的背景样式（可能是黄色背景块）。
### 3. 提示文案 (`.hint-text`)
- **内容**：“我当前训练数据还不够，可能有点傻呼呼的。你可以随时在此说出你的任何想法。感谢啦～”
- **样式**：字号 22px，颜色 `#373737`，加粗，居中对齐。
### 4. 反馈输入区域 (`.feedback-input-area`)
- **高度**：380rpx。
- **背景**：淡灰色 `#f9f9f9`，圆角 20rpx。
- **内容展示**：
  - `scroll-view` 显示当前的反馈文本 (`feedbackText`)。
  - 有内容时显示黑色文字，无内容时显示灰色占位符。
  - 底部留有 `100rpx` padding 以防内容被麦克风按钮遮挡。
### 5. 麦克风悬浮按钮 (`.mic-float-btn`)
- **位置**：输入区域底部居中 (`bottom: 20rpx, left: 50%`)。
- **样式**：圆形白色按钮，直径 90rpx，带阴影。
- **交互**：点击触发 `startRecordingProcess`。
### 6. 录音中覆盖层 (`.recording-overlay`)
- **显示条件**：`isRecording === true`。
- **样式**：白色半透明背景 (`rgba(255,255,255,0.98`)，完全覆盖输入区域。
- **子控件**（复用采访页录音样式）：
  - **取消按钮 (左)**：白色圆形按钮，点击触发 `onCancelRecording`。
  - **波形指示器 (中)**：深色胶囊背景 `#373737`，内含 6 条动态波形条 (`animation`) 和计时器文本。
  - **发送按钮 (右)**：白色圆形按钮，点击触发 `onStopRecording`（并未直接发送，而是停止录音并将文字填入）。
### 7. 底部操作按钮 (`.submit-actions`)
- **算了 (取消)**：灰色背景 `#f2f2f2`，带阴影。点击关闭弹窗。
- **告诉阿拓 (提交)**：
  - 渐变色背景 `#FFB9AC` -> `#E6AACF`，白色文字，加粗，带阴影。
  - **禁用逻辑**：若无文本且无录音，设置透明度 0.3。
  - **交互**：点击提交数据到后端接口 `/api/feedback/submit`。
## 当前还存在的问题 (待修复)
1.  **文字未累加**
    - **现象**：用户进行第二次录音时，生成的文本会覆盖掉第一次录音或输入的文本，而不是追加在后面。
    - **原因推测**：`startRecordingProcess` 中可能错误地重置了状态，或者 `onMessage` 回调中对 `feedbackText` 的更新逻辑有问题（未正确拼接旧文本）。
2.  **AI 头像尺寸与比例异常**
    - **现象**：用户反馈尺寸仍偏小，且原图是 1080x540 (2:1)，目前的显示效果不符合预期。可能是父容器宽度不够，或者 `aspectFill` 结合固定的宽高导致了视觉误差。
    - **需求**：需要准确还原 2:1 的比例，且尺寸要足够大以展示清晰。
3.  **录音控件计时逻辑 (正计时 vs 倒计时)**
    - **现象**：目前的录音计时是从 `00:00` 开始增加（正计时）。
    - **需求**：用户指出应该像采访页那样（或者是用户期望的那样）显示倒计时？需要确认采访页的确切计时逻辑（可能是 60s 倒计时）。如果采访页是倒计时，这里需要改为 `60 - seconds` 的显示逻辑。
4.  **样式细节**
    - **按钮颜色与阴影**：用户反馈中提到渐变色和阴影未生效，虽然代码中加了 `!important`，但可能受限于小程序组件的样式隔离或父级样式覆盖。
    - **倒计时显示**：在某些情况下可能不可见（颜色问题）。
